# Основа для следующего автономного документа

Этот файл передаёт опыт проекта `dtarburihopps-ai/doc` в новый чат.
Новая задача — похожий HTML, но другой Word-шаблон, поля и правила распознавания.
Использовать проверенные решения ниже; правила нового документа определить заново.

## Рабочая точка отсчёта

Согласованное состояние проекта: коммит `df6f7475b80bdd6c020c3cdf870c34fe385a9d88`.
Пользователь подтвердил правильную печать скачанного Word. Последний ролик принят;
он показывает обычный порядок действий, без плавающих фиолетовых рамок и экспериментов со сроком.

Новый документ делать отдельно, например в `documents/<имя-документа>/`, со своими
шаблоном, кодом, проверками и результатом. Существующую рассрочку и её файлы не перезаписывать.
Не запускать старые импортирующие и упаковочные скрипты для нового документа без адаптации путей:
они записывают результат в действующие `assets/` и `dist/`.

## Что удалось и подходит для повторного использования

- Один автономный HTML для Windows, открываемый двойным щелчком в Chrome или Edge.
  Интернет, ИИ, сервер и установка программ для работы самого HTML не нужны.
- Word-шаблон и библиотеки встроены в HTML. Сотруднику не нужно выбирать исходный Word,
  открывать папку через специальную кнопку или держать исходный DOCX рядом.
- Три области: произвольная информация от специалиста и кнопка «Распознать»;
  редактируемые поля; живой редактируемый предпросмотр итогового документа.
- Полностью ручное заполнение работает и при пустом исходном тексте.
  Ввод в поля сразу отражается в документе. Правки в документе сохраняются в скачанном Word.
- Парсер работает по явным правилам. Сотрудник может проверить и исправить результат.
  Нераспознанное значение не заменяется выдуманным. Лишние сведения не добавляются в документ.
- Вывод — DOCX на основе исходного Word, с сохранением его оформления.
  Кнопка «Скачать и распечатать» скачивает файл, затем его открывают и печатают в Word.
- Отдельную печать HTML из браузера убрали: не удалось надёжно сохранить размер,
  переносы, полосы бланка и колонтитулы. Не возвращать её по умолчанию.
- Скачивание идёт обычным способом браузера, в настроенную папку загрузок.
  HTML не может гарантировать конкретную папку при других настройках браузера.
- Город и год текущего проекта сохраняются одной кнопкой «Сохранить» в том же браузере.
  Это настройки администратора; кнопка не переписывает HTML и не переносит настройки коллегам.
  Данные покупателя после закрытия не сохраняются. Для нового документа уточнить нужные настройки.

## Что обязательно определить заново

Старые 50% первого взноса, три месяца, округление до сотен, диапазон 1–12 месяцев,
объединение слуховых аппаратов, исключение подарков и склонение срока относятся
к рассрочке. Они НЕ являются правилами следующего документа.
Также не переносить автоматически Сочи, 2026 год, реквизиты организации и список полей.

Сначала прочитать новый Word и примеры сообщений. Зафиксировать для каждого поля:

| Поле | Где находится в Word | Откуда брать и как распознавать | Если отсутствует/неоднозначно | Формат и ручная правка |
|---|---|---|---|---|
| Заполняется по новому шаблону | Все повторные вхождения | Метки, приоритеты, примеры | Пусто, предупреждение или согласованное значение | Согласовать для нового поля |

Отдельно определить вычисления, единицы, допустимые значения, даты, округление,
зависимости между полями и грамматику. Нужны реальные по форме, но вымышленные по данным
примеры: обычный, неполный, с лишней информацией и с неоднозначностью.
Не устраивать длинный опрос: сначала извлечь всё очевидное из файлов, затем спросить
только о недостающих решениях. Когда правила понятны, продолжать работу самостоятельно.

## Как сохранить Word без потери оформления

Брать новый утверждённый DOCX как основу. Не пересобирать договор вручную из HTML,
не перерисовывать дизайнерскую подложку и не заменять колонтитул напечатанной цифрой.
Сохранять изображения, размеры страницы, поля, стили, таблицы, разрывы, секции,
колонтитулы и настоящие поля Word, включая `PAGE`, если они есть в новом шаблоне.
Менять только согласованные переменные данные и требуемые динамические части.
Удалять из образца данные прежнего покупателя, сохраняя постоянный текст и реквизиты.

DOCX — ZIP с XML и связанными частями. Подстановки могут быть разбиты между несколькими
`w:r`/`w:t`; замена строки только в одном узле недостаточна. Использовать XML-обработку,
экранирование значений и точное сопоставление полей. Числа паспортов и других идентификаторов
не преобразовывать в числа: важны ведущие нули. Проверять все повторные вхождения.

Предпросмотр HTML — вспомогательный. Содержимое и оформление скачанного DOCX проверять отдельно.
Запрос Word об обновлении полей сам по себе не означает порчу документа; поля нумерации
оставлять настоящими. Не менять шаблон ради устранения такого запроса без необходимости.

Важное ограничение: это рабочий проект, а не готовый универсальный конструктор документов.
Основная логика находится в большом встроенном JS-пакете HTML, а не целиком в `src/`.
Для нового документа разумно выделить читаемые модули правил, состояния, подстановок и экспорта,
используя старую реализацию как проверенный образец. Сохранять лицензии встроенных библиотек.

## Ошибки, которые не нужно повторять

- Число месяцев, количество товара или номер из соседнего текста подменяет сумму.
- Строка вроде «Оплата картой» принимается за ФИО; инициалы разворачиваются в придуманные имена.
- Перерисовка предпросмотра во время набора сбрасывает курсор, удаляет пробелы или переносы.
- Ручная правка теряется при скачивании, смене несвязанного поля или отложенном обновлении.
- Новое распознавание незаметно сбрасывает ранее выбранный ручной режим вычисления.
- Пустые/ошибочные поля сопровождаются сообщением, что всё проверено.
- Форматирование ломается из-за пересоздания Word или изменения постоянной части шаблона.

Ручные значения, производные расчёты и значения по умолчанию должны иметь ясный приоритет.
Какие изменения пересчитывают зависимые данные — определить по новым правилам.

## Как проверять новый результат

1. По каждому новому полю: ручной ввод, распознавание, изменение в форме,
   изменение в предпросмотре и значение в скачанном DOCX. Проверить повторы, пробелы,
   переносы, ведущие нули, дефисы, «Ё» и специальные символы там, где они допустимы.
2. Проверить пустой текст, частичные данные, лишнюю информацию, неоднозначность,
   допустимые границы, зависимости и очистку. Ошибки показывать понятным языком.
3. Проверить ввод клавиатурой с паузами, выделение и редактирование в настоящем браузере.
   Просмотреть скриншоты, а не ограничиваться чтением исходника.
4. Проверить сам скачанный DOCX: целостность ZIP/XML, значения, оформление, изображения,
   колонтитулы, номера страниц и динамические части. Проверить работу без сети.
5. Честно отделять проверку в облачном Chromium/Linux от Windows, Microsoft Word и принтера.
   Проверки XML не равны реальной печати. Старые 2494/70/484 проверки не подтверждают
   работоспособность нового шаблона; нужны проверки нового набора правил.

Обычный HTML не может автоматически читать соседний DOCX из папки без участия пользователя.
Успешный рабочий вариант — встроенный шаблон. Не возвращаться к выбору папки,
ручной загрузке шаблона администратором или запуску сервера как обязательному действию.

## Обучение и передача файлов

Инструкцию и видео делать, когда они понадобятся, по окончательному интерфейсу.
Администраторам нужны короткие команды и порядок нажатий, без внутреннего устройства программы.

- Если в новом документе есть сохраняемые настройки: шаг 0, один раз, повторять при изменении.
- В памятке: сначала общий вид в состоянии нужного шага, затем крупный план.
  После распознавания показывать заполненную форму, при проверке — заполненный документ.
- Стрелку вести от текста действия к соответствующей области. Настройки не включать
  в рамку области ввода сообщения. Не добавлять ссылки «Дальше»/«Наверх» и лишние советы про Ctrl+C/V.
- В видео: курсор, клики, шаг за шагом. Не использовать плавающие фиолетовые рамки;
  не превращать ролик в демонстрацию возможностей. Страницы при проверке помещать целиком в кадр.
- PDF сжимать за счёт общих видов; крупные планы и текст оставлять чёткими.
  MP4 готовить для воспроизведения до окончания загрузки (`faststart`).
- Для сотрудников передавать HTML в ZIP. Ссылка на raw HTML в GitHub показывает исходный код,
  а некоторые корпоративные диски блокируют HTML или неправильно отдают его для скачивания.
- Указывать ссылку на конкретный коммит и проверять скачивание опубликованного файла,
  его размер и совпадение байтов. Локальные пути `/workspace/...` и `sandbox:` здесь не оказались
  надёжным способом передачи. PDF и MP4 можно передавать отдельными прямыми ссылками.
