# Как здесь получили настоящие скриншоты и PDF

Рабочие примеры: `training/admin-guide/capture.cjs` и `training/admin-guide/build.py`.
Скриншоты и инструкция рассрочки созданы автоматически в облачной среде;
пользователь не присылал запись экрана для их изготовления.

## Сначала определить, что именно недоступно

Отказ браузерного инструмента открыть `file://...` не доказывает, что невозможно
снять скриншот приложения или создать PDF. В соседнем чате могут быть другой набор
инструментов, другая среда или другие ограничения: это нужно проверить отдельно.
Не обходить явные запреты доступа; использовать разрешённые средства среды.

В этом проекте сработал такой способ:

1. Прочитать автономный HTML из рабочего каталога.
2. Отдать его через временный HTTP-сервер на `127.0.0.1`.
3. Открыть этот адрес в установленном Chromium через Playwright.
4. Нажимать настоящие элементы формы, вводить учебные данные и сохранять PNG.
5. Собрать PDF из этих PNG, текста, стрелок и рамок через Python/ReportLab.
6. Отрендерить готовый PDF через PyMuPDF (`fitz`), посмотреть страницы и проверить вёрстку.

Сервер нужен только разработчику при съёмке. Он не входит в комплект для администраторов.
Не предлагать пользователю localhost-ссылку как способ получить готовую инструкцию.

## Проверить инструменты в своей среде

Из корня подключённого репозитория:

```sh
node -p 'require.resolve("playwright/package.json")'
command -v chromium
command -v ffmpeg
python -c 'import reportlab, fitz; print("PDF tools available")'
```

Для статичных скриншотов FFmpeg не нужен. Он нужен для видео.
Здесь Chromium находится в `/usr/bin/chromium`; другой путь можно передать через
`CHROMIUM_PATH`. Использовать доступную среде установку; если зависимости отсутствуют,
сначала проверить разрешённый способ их установки и фактическую причину ошибки.
Отсутствие одного browser-инструмента не заменяет эту проверку.

## Быстрый пробный скриншот нового HTML

```sh
node tools/capture-offline-html.cjs "/путь/к/новому.html" /tmp/new-form.png "body"
```

Это общий вспомогательный скрипт: он не перезаписывает приложение и файлы рассрочки.
Для асинхронной формы вместо `body` передать селектор реально готового предпросмотра.
Для рассрочки, например, `#preview [data-bind]`.
Выбрать новое имя PNG: скрипт защищает уже существующий файл от перезаписи.

После успешной пробы адаптировать сценарий съёмки под новый документ:
ввести город и год; внести специалистов, каждого с новой строки; сохранить;
проверить сохранённый список и выбор специалиста для очередного бланка;
заполнить один вымышленный пример. Селекторы брать из нового HTML, не угадывать
и не копировать имена полей рассрочки. Если настройки должны переживать перезагрузку,
проверить их после `reload`, прежде чем показывать этот шаг как работающий.

Для PDF нужны скриншоты последовательных состояний формы, а не обязательная видеозапись.
Готовый пример такого сценария — `training/admin-guide/capture.cjs`.
Не запускать его без адаптации для другого HTML: он привязан к рассрочке и перезаписывает её учебные PNG.

## Сборка PDF в уже согласованном оформлении

`training/admin-guide/build.py` использует ReportLab, Pillow и DejaVu Sans.
Читаемые кириллические шрифты, макет страниц, текст, стрелки и оформление уже есть.
Сделать отдельную копию/адаптацию для нового документа с собственными путями;
не перезаписывать `dist/staff-guide.pdf` рассрочки.
Оригинальную памятку рассрочки использовать как образец оформления, а её фактические шаги
заменить новыми. Общий вид показывать в состоянии нужного шага, затем — крупный план.

PDF здесь не печатается через браузер. Поэтому недоступность браузерной кнопки печати
не мешает программно собрать инструкцию. Для проверки страниц используется
`fitz.open(path)` и `page.get_pixmap()`; полученные изображения нужно посмотреть.

## Что сообщить пользователю, если всё-таки не получилось

Назвать конкретную операцию и фактическую ошибку: не найден файл, отсутствует Chromium,
нет Playwright, запрещён запуск процесса или локальный сервер, не разрешён доступ
к исходнику, отсутствует библиотека PDF. Проверить оставшиеся допустимые способы.
Только подтверждённое ограничение, которое не удаётся устранить разрешённым способом,
может сделать запись пользователя необходимой. Не объявлять такую необходимость по одному
отказу инструмента открытия локального HTML. Не утверждать, что увидел интерфейс,
если удалось только прочитать его исходный код.
