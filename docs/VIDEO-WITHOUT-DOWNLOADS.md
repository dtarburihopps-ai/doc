# Как самостоятельно записать видео HTML: рабочий способ

Готовый текст для передачи задачи новому чату: [VIDEO-CHAT-PROMPT.txt](VIDEO-CHAT-PROMPT.txt).

Этот инструктаж для ассистента нового чата. Здесь уже создан настоящий MP4
из действий в HTML: `dist/staff-walkthrough.mp4`. Пользователь не снимал экран
и не присылал кадры для его изготовления. Средства конкретного нового чата
нужно проверить: их наличие нельзя обещать без проверки.

Если этих файлов ещё нет в старом checkout нового чата, прочитать актуальный файл
в GitHub либо сделать `git fetch origin` и `git show origin/main:docs/VIDEO-WITHOUT-DOWNLOADS.md`.
Сохранить собственные изменения нового проекта; не сбрасывать их ради получения инструкции.

## Самая важная развилка

Playwright `recordVideo` может потребовать **свою** сборку FFmpeg и выдать:

```text
Executable doesn't exist at .../ms-playwright/ffmpeg-1011/ffmpeg-linux
Video rendering requires ffmpeg binary
Please run: npx playwright install ffmpeg
```

Это не доказательство, что в машине нет FFmpeg или что видео записать невозможно.
В этом проекте именно такая ошибка уже была. Загрузка сборки Playwright с CDN
вернула 403, но установленный `/usr/bin/ffmpeg` работал. Итоговую запись сделали
через **Chromium CDP → JPEG-кадры → системный FFmpeg → MP4**.
Для этого способа `recordVideo` и скачивание его FFmpeg не нужны.
Не отключать проверки загрузок, не подменять исполняемые файлы Playwright,
не менять политики безопасности. Использовать установленный системный инструмент.

## 1. Проверить то, что уже доступно

В каталоге подключённого репозитория:

```sh
node -p 'require.resolve("playwright/package.json")'
command -v chromium
command -v ffmpeg
command -v ffprobe
ffmpeg -hide_banner -encoders
```

Здесь доступны Playwright, `/usr/bin/chromium`, `/usr/bin/ffmpeg`, `/usr/bin/ffprobe`
и кодировщик `libx264`. Пути в другом чате могут отличаться.
Установленный Chromium запускается через явный `executablePath`;
не нужно автоматически скачивать другой браузер из-за отсутствия кеша Playwright.
Если инструмента действительно нет, проверить разрешённую установку и конкретную ошибку.
Сбой одного скачивания не заменяет эту диагностику.
Если `require('playwright')` работает, для приведённого способа не нужен `npx`:
не устанавливать заново Playwright только из-за того, что `npx` пытается скачать другой пакет.

## 2. Сначала получить короткий MP4, без разработки всей инструкции

Готовый общий модуль: `tools/system-video-recorder.cjs`.
Он принимает обычную Playwright-страницу Chromium, сохраняет паузы чтения,
использует системный FFmpeg и создаёт H.264/yuv420p MP4 с `faststart`.
Существующий выходной файл не перезаписывается.
Вызвать `recording.stop()` нужно **до** закрытия страницы или браузера и дождаться результата.

На полностью неподвижной странице CDP может не прислать кадр до первого действия.
Поэтому модуль сам получает начальный кадр через `page.screenshot()`, затем записывает
реальные обновления CDP. Он не блокирует начало сценария ожиданием такого события.
В результате `updates` показывает количество полученных обновлений: для сценария,
который меняет форму, нужно убедиться, что они были.

Ниже самостоятельная проверка на реальном HTML рассрочки. Её можно запустить
из корня репозитория: исходники, шаблон и готовый ролик не изменятся.
Это проверка способа записи, а не готовая инструкция для другого бланка.

```sh
node - <<'JS'
const fs=require('fs'),path=require('path'),http=require('http');
const {chromium}=require('playwright');
const {startPageRecording}=require(path.resolve('tools/system-video-recorder.cjs'));
(async()=>{
 const html=fs.readFileSync('dist/Договор рассрочки.html');
 const server=http.createServer((q,r)=>{r.setHeader('Content-Type','text/html; charset=utf-8');r.end(html)});
 await new Promise(r=>server.listen(0,'127.0.0.1',r));
 let browser,recording,result;
 try{
  browser=await chromium.launch({executablePath:process.env.CHROMIUM_PATH||'/usr/bin/chromium',headless:true,args:['--no-sandbox']});
  const page=await browser.newPage({viewport:{width:1600,height:1000}});
  await page.goto('http://127.0.0.1:'+server.address().port);
  await page.waitForSelector('#preview [data-bind]');
  const output='/tmp/browser-video-proof-'+Date.now()+'.mp4';
  recording=await startPageRecording(page,output);
  await page.waitForTimeout(1200);
  await page.fill('#source','Попов Владимир Геннадьевич\nПравое ухо: Terra BTE-SP\nИтого 74000');
  await page.click('#recognize');
  await page.waitForTimeout(2200);
  if(await page.inputValue('#fullName')!=='Попов Владимир Геннадьевич')throw Error('Recognition did not complete');
  result=await recording.stop();
  if(result.updates<2)throw Error("No live interface updates were captured");
  console.log(JSON.stringify(result));
 }finally{
  if(recording)await recording.stop();
  if(browser)await browser.close();
  await new Promise(r=>server.close(r));
 }
})().catch(e=>{console.error(e);process.exitCode=1});
JS
```

После этого проверить файл через `ffprobe` и извлечь из MP4 кадр через FFmpeg.
Посмотреть изображение: файл должен содержать интерфейс и изменившиеся данные.
Одного появления файла или успешного импорта библиотеки недостаточно.

## 3. Адаптировать последовательность под новый бланк

Источники готовой инструкции:

- `training/admin-video/record.cjs` — настоящие клики, ввод, прокрутка, сохранение,
  проверка заполненного Word, запись CDP и сборка финального видео.
- `training/admin-video/shell.html` — курсор, анимация нажатия, нейтральные всплывающие
  подсказки и рамки, следующие за элементами при прокрутке и приближении.
- `tools/system-video-recorder.cjs` — только общая запись, без привязки к рассрочке.

Скопировать/адаптировать сценарий в папку нового проекта. Пути к новому HTML и результатам
задать отдельно: не запускать полный старый сценарий без адаптации, иначе он перезапишет
`dist/staff-walkthrough.mp4` рассрочки. Селекторы брать из нового HTML.

Для нового бланка со специалистами показать реальную последовательность:

1. Ввести город и год.
2. Ввести вымышленных специалистов — каждого с новой строки — и сохранить.
3. Показать сохранённый список. Если заявлено сохранение между открытиями,
   перезагрузить страницу и убедиться, что список восстановился.
4. Выбрать специалиста предусмотренной кнопкой для очередного бланка.
5. Заполнить один учебный бланк, один раз показать «Проверьте все данные», скачать результат.

Сначала выполнить действия и проверить итог, затем выдавать ролик как завершённый.
Не показывать статическую картинку как якобы работающий интерфейс.
Проверять сохранённые настройки через `reload` в том же browser context и на том же
адресе сервера: новый контекст или другой порт могут дать другое хранилище.

## 4. Курсор и оформление: что уже согласовано

CDP не гарантирует видимость системного курсора. В записи рассрочки курсор нарисован
поверх настоящей страницы, а реальные клики выполняются Playwright.
Использовать этот готовый подход, не путать отсутствие стрелки с отсутствием записи.

В `shell.html` есть `lesson.show(title,body,target,side)`, `lesson.target(...)`,
`lesson.cursor(x,y)` и `lesson.press(down,x,y)`. Они работают с формой в своём iframe:
сервер отдаёт оболочку на `/`, новый HTML — на `/app`. Селектор target относится к HTML формы.

- Постоянных панелей сверху и снизу нет. Команды короткие, во всплывающем окне с фоном
  и нейтральной обводкой, рядом с текущей областью.
- Рамки рассчитываются по DOM при прокрутке, обновлении формы и масштабировании.
  Не рисовать рамку один раз по старым координатам.
- Для указателя использовать фактический `locator.boundingBox()` в координатах всей страницы.
  Клик — реальное нажатие с видимой анимацией: сжатие курсора и расходящийся круг.
- Не повторять несколько раз проверку одних полей и не демонстрировать лишние варианты.
  После заполнения достаточно одного «Проверьте все данные».
- Страницы документа при проверке помещаются в кадр целиком. Учебные данные вымышленные.

Нативные окна Word/Windows в этой облачной среде не записывались. В конце ролика
инструкция открыть скачанный Word даётся текстом; не подделывать запись запуска Word.

## 5. Проверка и передача результата

Проверить весь MP4 на ошибки декодирования, метаданные через `ffprobe`, кадры каждого шага,
правильность рамок и сохранение результата. Воспроизведение должно начинаться до полной
загрузки (`faststart`); файл не должен раздуваться без необходимости.
Финальные исходники и видео нового бланка сохранять отдельно. При публикации в GitHub
дать ссылку на конкретный коммит и проверить HTTP-ответ и байты скачанного файла.

Пользовательская запись не требуется для описанных действий в HTML, **если этот путь
доступен в среде**. Перед просьбой записывать экран самостоятельно назвать конкретный
подтверждённый блокер и результаты проверки допустимых вариантов. Не выдавать ошибку
отдельного инструмента или необязательной загрузки за общий запрет на создание видео.
При явном запрете запуска процесса, сервера или доступа к файлу не обходить этот запрет.
